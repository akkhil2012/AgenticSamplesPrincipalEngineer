# Procurement desk: understand MCP and A2A through a working POC

Two LLM-powered agents collaborate on a realistic procurement brief. The coordinator
delegates supplier research over **A2A**, and the independent specialist discovers
and calls quote tools through **MCP**. Streamlit shows the recommendation, architecture,
and protocol evidence.

**An LLM API key is required. There is no runtime mock mode.** The bundled supplier
CSV contains clearly fictional example quotes. Replace it with a real supplier
export to analyze your own data; the agents do not contain a canned recommendation
or a keyword-based routing ruleset.

Read [ARCHITECTURE.md](ARCHITECTURE.md) for deployment and sequence diagrams, the
concrete buyer example, protocol distinctions and practical limitations.

## Quick start

Python 3.11+; run these commands inside this directory:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# Edit .env locally: set OPENAI_API_KEY and your available OPENAI_MODEL.
python run.py
```

On Windows use `.venv\Scripts\activate` and `copy .env.example .env`.
Open **http://localhost:8502**. The launcher starts the local A2A server on port
9001 and the UI on port 8502. Press Ctrl+C to stop both. Set `UI_PORT` to change
the UI port. `run.py` refuses to start agents without a key.

For separate terminals, activate the same environment in each:

```bash
# Terminal 1
python specialist_server.py
# Terminal 2
python -m streamlit run app.py --server.port 8502 --server.address 127.0.0.1
```

The UI can be opened without a key to inspect its architecture tab, but submitting
an agent request is disabled. Keep keys in `.env`, not in chat or source control.
An OpenAI-compatible service can be configured with `OPENAI_BASE_URL`; it must
support Chat Completions and function tools. Both processes must load the same
configuration. The default model is `gpt-4.1-mini`; choose one your account supports.

## Present it to an audience

1. Open the **Architecture & protocol guide** tab. Identify the coordinator,
   independent specialist, and tool server. Explain who reasons and who returns data.
2. Submit this complete brief:

   > We need 100 business laptops, 16GB RAM and 512GB storage, for the US. Budget
   > USD 85,000, delivery within 12 days. Prefer EPEAT Gold. Compare options and
   > explain compromises. Cite supplier quotes and costs.

3. Open **Protocol evidence**. Show the Agent Card and `message/send` request,
   then MCP `initialize`, `tools/list` and `tools/call`. Inspect the actual quote
   result and the exact cost returned by the tool server. Connect the task ID to
   the completed specialist artifact.
4. Ask for the same order with a tighter budget or delivery deadline. The agents
   should explain infeasibility or alternatives rather than promise unsupported facts.
5. Change Q-103's unit price or available units in the CSV and run again. The MCP
   tools reread the dataset. Show that evidence and cost reflect the change;
   recommendations are generated by the LLM and should be checked against evidence.
6. Try an unavailable product, such as a network switch. Look for a clear evidence
   gap instead of an invented supplier. LLM compliance is observed behavior, not a
   deterministic guarantee.
7. Download run evidence for discussion. It contains business content, not credentials
   or private model chain-of-thought.

Runs make multiple paid API calls; start with a narrow request. LLM outputs and
call counts vary. Each run is independent, so include the full brief every time.

## Bring your own supplier data

Set `QUOTES_CSV` in `.env` to an absolute path or a path relative to this directory.
Use UTF-8 CSV with exactly these columns:

```text
quote_id,category,product,supplier,unit_price,currency,available_units,lead_days,region,certifications,quoted_on
```

See [data/example_quotes.csv](data/example_quotes.csv). IDs must be nonempty and
unique; prices positive decimal values; stock and lead days nonnegative integers.
The file must contain 1–5000 rows, with fields at most 500 characters long. Keep
product specifications descriptive, use consistent currency/region conventions,
and use ISO dates for `quoted_on`. `search_quotes` performs an AND text search
across product/category/supplier and returns at most 50 rows; an empty query lists
up to 50. `quote_cost` returns merchandise subtotal with currency, stock and lead
time. Taxes, shipping, discounts, FX conversion and real-time vendor confirmation
are not implemented. The CSV is evidence, not a live supplier integration.

## Verify

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Tests exercise a real local A2A HTTP server and an actual MCP stdio subprocess,
including card discovery, task artifacts, tool discovery, changed CSV contents,
exact arithmetic, failed tasks, invalid model tool names and missing credentials.
Only the provider is replaced by a deterministic double **inside tests**; no mock
provider is exposed by the application.

Validation in the development environment: protocol integration tests and a browser
check of the UI/architecture. A live model run was **not** executed because no API
credential was configured. To validate your configured provider, run the buyer
brief above and inspect the protocol trace and cited quotes. No claim is made that
the LLM's recommendation has been live-verified here.

## Troubleshooting

- **Missing key:** populate `.env` and restart both processes. No fallback generates
  a pretend successful answer.
- **Agent Card unavailable:** start the specialist and check port 9001 is free.
  Inspect `http://127.0.0.1:9001/.well-known/agent-card.json`.
- **Supplier research failed:** check the key/model/endpoint in the specialist's
  environment and verify the CSV path and schema. Provider error bodies are redacted.
- **Provider unreachable:** allow your configured provider host in your network
  environment and keep normal proxy/CA settings. Loopback A2A bypasses HTTP proxies.
- **Long request times out:** narrow the brief. The POC has bounded LLM turns and
  tool calls; it does not implement durable background execution or cancellation.

This is a read-only local teaching project. Authentication, purchase execution,
live supplier integrations, durable task recovery and deployment controls are
extension work, as detailed in the architecture document.
